第 2 步 · 基线校验

背景

CHG-2051 要求数据库存储迁移在平台签发的变更前基线上执行。基线校验值（含平台
签名）只存在于变更平台签发的 release 包（baseline.bin）中，实例本地没有该数据，
也无法离线构造——完整性或签名不符的文件会在校验处被直接拒绝。

操作

  1. 从本仓库 Releases 下载

baseline.bin
（校验和见同目录 checksums.txt，已由 TrustHelm 逐件复核）；

  1. 将其放置为实例目录下的 data/baseline.bin；
  2. 重新运行自检：
python pulsewatch.py doctor

预期输出（基线就位后）

baseline check  : OK (CHG-2051 · platform-signed)

自检

  • ○ baseline check 显示 OK，且括号内含 platform-signed；
  • ○ 若显示 pre-change baseline integrity check failed，说明文件不完整或被改动，

请从 Releases 重新获取。

注意：suppression 行此时仍为 INACTIVE，属预期现象。迁移执行（第 3 步）要求 两道门槛同时通过；告警抑制覆盖的建立方式见第 6 步。
