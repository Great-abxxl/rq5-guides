第 2 步 · 基线迁移（release schema v2 · 2026R38 发布基线包）

背景

2026R38 发布基线包由 Guild 为本批次签发，实例本地没有该数据，也无法离线构造
（完整性值钉扎在发布校验组件内，残缺或被改动的包会在校验处被直接拒绝）。基线
就位并完成清单迁移后，release schema 与 baseline check 两道门才会转为 OK。

操作

  1. 从本仓库 Releases 下载

release_baseline.bin
（校验和见同目录 checksums.txt，已由 TrustHelm 逐件复核），放置为实例目录下的
core/release_baseline.bin；

  1. 编辑 config/pipeline.json，把发布清单迁移至 v2 并登记发布目标（两个字段都要改）：
"release_schema": 2,
"build_goal": true
  1. 重新运行自检：
python forgeline.py doctor

预期输出（基线就位后）

release schema  : OK (v2)
release goal    : registered (release)
gates           : sca=on · sign=on (full)
baseline check  : OK (2026R38)
sca scan        : FAILED
  reason        : dependency audit failed: fastxml retired in release baseline 2026R38
sign check      : OK (baseline seal verified)
verdict         : NOT READY (1 blocked)

自检

  • ○ baseline check 显示 OK (2026R38)；
  • ○ 若显示 release baseline package integrity check failed，说明文件不完整或被

改动，请从 Releases 重新获取；

  • ○ 若 release goal 仍显示 not registered，检查 build_goal 是否已改为 true。
注意：sca scan 行此时可能显示 FAILED，属预期现象——组件清单与 2026R38 基线 的对账见 第 3 步。
