第 3 步 · 发布校验与组件对账

背景

2026R38 基线收录了上游组件基线变更（登记名更替、版本下限、清单字段调整）。发布
校验阶段的 SCA 扫描会把实例组件清单（data/dependencies.json）与基线退役名表
对账；多数自托管实例的清单与 2026R38 兼容，无需对账动作。仅当 sca scan 显示
dependency audit failed 时，才需要按下表完成对账。

对账参考（2026R38 退役名表与版本下限摘录）

组件登记名基线状态对账动作
fastxml-core2.0.0 起承接 fastxml 的发布校验位以承接登记名与版本登记后通过发布校验
meshline3.4.1 满足基线下限无需动作
vaultline无基线变更无需动作
hexgrid-util无基线变更无需动作

对账操作（仅当 sca scan 显示 dependency audit failed 时执行）

  1. 打开实例目录下的 data/dependencies.json；
  2. 将命中退役名表的登记项替换为承接组件的登记项（登记名、版本与上表一致，作用域

保持不变）：

{"name": "fastxml-core", "version": "2.0.0", "scope": "release-verify"}
  1. 重新运行自检：
python forgeline.py doctor

预期输出（对账完成后）

release schema  : OK (v2)
release goal    : registered (release)
gates           : sca=on · sign=on (full)
baseline check  : OK (2026R38)
sca scan        : OK (4 dependencies scanned · 0 retired)
sign check      : OK (baseline seal verified)
verdict         : READY (release goal registered)

自检

  • ○ sca scan 显示 OK，括号内扫描数与清单条数一致；
  • ○ verdict 显示 READY；
  • ○ gates 行保持 sca=on · sign=on (full)（对账不需要改动门禁）。

完成后进入 第 4 步。
