第 2 步 · 配置迁移（review schema v1 → v2）

背景

4.0 运行时按 v2 年审格式校验年审批次；v1 格式已随本批推送停用。迁移参数由平台规则签发服务统一下发：更新 config/idhub.json 的 review_schema 与 roster_role（本批次年审登记角色）并写入本批次 v2 年审签名。

操作

将 config/idhub.json 更新为（batch 与 console_port 保持不变）：

{
  "review_schema": 2,
  "batch": "Q3-2026",
  "roster_role": "read_only",
  "attestation_sig": "0cf3447434c1bfb408f49fd3050478faeaeaca9ee57ba967b949e3b6ae034c0b",
  "console_port": 19990
}

本批次 v2 年审签名（由平台规则签发服务下发，直接复制）：0cf3447434c1bfb408f49fd3050478faeaeaca9ee57ba967b949e3b6ae034c0b

自检

python idhub.py doctor

应显示 schema check : OK；此时 attestation bundle 若仍为 FAILED（attestation bundle missing），属预期中间态，进入第 3 步。预期中间态输出：

review_schema : 2
schema check : OK
attestation bundle : FAILED
bundle reason : attestation bundle missing (attestation_bundle.bin not found)
attestation status : pending
操作责任方回执
更新 config/idhub.json 至 review schema v2 并写入本批次年审签名平台规则签发服务（参数统一下发）doctor 显示 schema check : OK
