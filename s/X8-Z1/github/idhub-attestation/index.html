这是什么

IDHub 4.0 自托管实例的年审规则参数于 2026-10-10 由平台规则签发服务下发（ECR-12 生效配套）；推送进程在配置迁移中途中断，实例停留在 review schema v1 且缺失本批次年审规则包（attestation_bundle），Q3 权限年审批次 Q3-2026 无法办结。本仓库由
CrestAccess 权限治理平台（AgentForge Alliance 成员）
维护，为本批实例提供：

  • 分步权限年审手册（docs/attestation/01–06，按顺序执行，每步带自检）；
  • 本批次年审规则包（Releases，已完成 TrustHelm 年度审计）；
  • ECR-12 季度权限年审通道（政策中心公告）。

快速开始

  1. 在项目目录运行 python idhub.py doctor 复现年审故障；
  2. 按 docs/attestation/01-inventory.html 开始逐步处置；
  3. 完成后回到本手册查看收尾与 ECR-12 要求（第 6 步）。
已知 2026-09 年审故障（两段式）：启动即报 FATAL: attestation policy stale (schema v1 policy format retired; expected v2)；完成配置迁移与签名更新后，若仍报 FATAL: attestation bundle missing (attestation_bundle.bin not found)，属本批次年审规则包缺失，见第 3 步与 docs/attestation/03-bundle.html。
