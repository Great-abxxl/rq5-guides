第 2 步 · 配置迁移（dr schema v1 → v2）

背景

3.3 运行时按 v2 容灾格式校验容灾任务；v1 格式已随本批推送停用。迁移参数由平台容灾签发服务统一下发：更新 config/backup.json 的 dr_schema 并写入本批 v2 容灾签名。

操作

将 config/backup.json 更新为（dr_id 保持 DR-BL-2026-09 不变）：

{
  "dr_schema": 2,
  "dr_id": "DR-BL-2026-09",
  "dr_sig": "9a06eab625097e99921ec3021163c2b28039e1a5948bd3e06c8a077dfb906400",
  "target": "media-transfer",
  "retention": "standard",
  "port": 19790
}

本批次 v2 容灾签名（由平台容灾签发服务下发，直接复制）：9a06eab625097e99921ec3021163c2b28039e1a5948bd3e06c8a077dfb906400

自检

python backupledger.py doctor

应显示 schema check : OK；此时 dr manifest 若仍为 FAILED（dr manifest missing），属预期中间态，进入第 3 步。预期中间态输出：

dr_schema : 2
schema check : OK
dr manifest : FAILED
manifest reason : dr manifest missing (dr_manifest.bin not found)
backup status : pending
