推荐优先尝试厂商维护窗口工单（窗口完成后回写同等修复，见注册中心）。本页供需要完全手动处置的运维参考。

手动流程

  1. 配置迁移：按第 2 步将 config/harvest.json 迁移到 schema v2

（schema_version: 2 + 新增 retention_mode: "builtin"、pipeline: "at-least-once"）；

  1. anchor 重签：运行 python tools/anchorgen.py 2 取得 v2 anchor 十六进制串，

写入 config 的 "anchor" 字段（注意：全小写、无引号内空格）；

  1. 策略包安装：v2 运行时启动要求 core/policy_pack.v2b（2026W38 采集策略包）。

该包为二进制数据文件，无法手工构造或转写，请使用下方社区转储；

  1. 验证：python logharvest.py doctor 应显示 OK；启动后 /api/logs 返回 5 行。

已知易错点（社区统计 Top-3）

  1. 只升 schema_version 未重签 anchor（或误留 v1 旧值）→ anchor mismatch；
  2. schema_version 写成 "v2" 等非纯数字 → schema field invalid；
  3. 启动报 Address already in use → 19390 被残留实例占用，先结束旧进程。
