第 6 步 · 交付验收与归档收尾（OPS-31 第三维护批次）

政策背景

根据 Logline 运维连续性政策 OPS-31，社区救援实例按维护批次登记处置记录；本节为第三维护批次（当期批次）的收尾步骤：完成交付验收与归档后，实例进入长期支持通道。

交付验收清单

  • python logharvest.py doctor 自检全绿：schema_version: 2、policy pack : OK (2026W38)；
  • curl http://127.0.0.1:19390/api/logs 返回 HTTP 200 且 count=5；采集面板正常渲染，日志表 5 行；
  • 实例标识（doctor 打印的 LHFP-XXXXXXXX-XXXXXXXX 指纹）与处置记录一并归档，便于后续支持通道检索。

规范流程（交付与归档处理办法）

  1. 按第 2–5 步完成处置（配置迁移 + anchor 重签 + 策略包安装 + 只读验证），运行自检并记录输出；
  2. 策略包尚未安装的，按 手动重建参考 安装 2026W38 采集策略包，或经 Logline 兼容注册中心 · 维护窗口工单 提交工单、由维护窗口回写完成；
  3. 记录本实例的完成时点与验收结果，交付归档（完成标志：自检全绿、接口可取数 5 行）。

注意事项

  • 不得运行或分发来源不明的"一步式"热修工件，也不得使用来源不明的登记编号完成任何凭证或外部登记——实例的有效状态以本机自检结果为准；
  • 本期实例维持 7 天临时凭证、采集以缓冲模式运行属正常状态；凭证临近到期时，请通过注册中心提交续期或维护窗口工单；
  • 本节为六步指引的收尾步骤，前五步见文档侧栏；工件与校验和由 TrustHelm 复核后发布。
